# v0.6.2 연산 복구 및 그림 수정

운영 UI 확인: Cycle 3 / Evidence r242, 후보 208개, simulation batches 0, SCIENTIFIC_REVIEW, 승인 0/6.

보고서 생성이 미실행 프로젝트를 report_ready로 바꾸고 Cron이 제외하는 결함을 수정했다. 진행 보고서는 draft로 응답하고 running/compute 상태를 유지한다. 기존 report_ready/complete라도 현재 주기에 pending 후보가 있으면 Cron이 다시 포함한다. 인간실험 HOLD 마커가 미평가 후보의 실행을 막지 않는다.

누락된 초기 작업은 100개 이내 일괄 복구한다. 실행 중 작업/기존 탐색 결과는 중복하지 않는다. 후보별 최종 실패 작업 3개가 있으면 무한 재시도하지 않으며 작업 오류를 확인해야 한다. 프로토콜은 기존 무결성 규칙에 따라 연산 전 동결한다. 연산 시작 후 프로토콜 변경은 여전히 차단한다.

강건 검증은 최초 60개를 반복해서 조회하던 오류를 고쳐, historical/stress 결과가 누락된 다음 후보들도 순차적으로 실행한다.

미실행 후보는 UNEVALUATED로 집계하며 실패와 구분한다. 과거 revision의 인간 CONFIRM은 현재 CONFIRMED로 끌어오지 않는다. 모든 검증층이 미검증이면 최종 생존율은 0이다. 전원 0%인 추정기에 최고 성능 서술을 만들지 않는다.

그림 6·7은 데이터 유무에 관계없이 SVG를 생성한다. 데이터가 없으면 검증 대기를 명시한다. 보고서 다운로드 시 기존 그림 참조도 해석할 수 있다. 공개 화면에 미평가 건수를 추가했다.

승인은 실제 G1~G6 결과로만 성립한다. 이 수정은 승인 수나 통계 판정을 인위적으로 올리지 않는다. 배포 후 Cron 또는 자동 진행 1회로 복구가 시작되며 결과 계산과 사람의 학술 승인까지 완료되어야 승인 수가 증가한다.

검증: 전체 테스트 123개 중 120개 통과, 3개 환경 의존 스킵, 실패 0. 새 회귀 검증은 보고서 후 복구/중복 방지, 미평가 집계, 전층 N/A 생존율, 그림 대기 SVG, 60개 초과 강건 검증을 포함한다. 운영 데이터에는 쓰기를 수행하지 않았다.

배포 순서: 기존 0019까지 적용된 환경에서 `npm run db:migrate:remote` 후 `npm run deploy`. 추가 마이그레이션 0020은 인덱스만 생성하며 연구자료를 삭제하지 않는다.
