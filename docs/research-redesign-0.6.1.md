# 연구 재설계 소스 수정 — 0.6.1

## 확인한 원인과 수정

- τ·d가 0으로 축소되는 경로: 측정값이 null이어도 Number(null)이 0이 되어 기존 수준을 덮어썼습니다. 이제 운영 관측에 따른 설계 변경은 grid_source=operational인 경우에만, 비어 있지 않은 유효한 값으로 수행합니다. 선언한 설계 수준과 첨부 CSV는 자동 축소하지 않습니다.
- EMA·Change-point 신뢰도: 초기 상태의 p=1이 남아 confidenceFor가 갱신된 var 대신 p를 선택했습니다. 네 추정기에 동일한 의미의 이전 단계 예측 잔차 EWMA 분산을 적용하는 residual_common_v1을 추가했습니다. 정답은 신뢰도 계산에 사용하지 않습니다. 기존 방식은 오프라인 절제 검사에 보존했습니다. 공통 정의가 확률 교정을 보장하지는 않습니다.
- 지연: 승인 d를 실제 검토 지연 비용에 반영합니다. 인간 모델의 응답시간(초)은 86400으로 나누어 일 단위로 환산하고 d에 더합니다. 인간 모델의 mean_delay가 d를 덮어쓰지 않습니다. 자율 실행 지연은 별도 설계 상수입니다. d는 승인 비용·시간 경로이며 미래 집행시점의 정답 변화까지 모형화한 것은 아닙니다.
- 실험에서 추정한 불필요 개입률은 이미 AI 정답에 조건부인 비율이므로 신뢰도 계수를 다시 곱하지 않습니다. 검토자 모수는 현재 revision의 실제 표본 기준을 충족한 모델만 재계산에 사용합니다. 검증 전 설계 prior 사용을 실행 기록에 표시합니다. 제시된 q≈0.28, u≈0.19를 확인된 실측치로 자동 승격하지 않았습니다.

## 208개 후보와 제약

data/redesign_candidates.csv는 사용자 첨부 파일을 보존한 것입니다. 192개 paired_core 후보는 16개 base마다 τ={0,1,2} × d={0,1,2,4}를 모두 포함합니다. 첨부의 anchor_K0/anchor_K1 16개는 내부적으로 anchor로 표시합니다. base 공변량 고정, 수준, 중복과 행 수를 서버에서 검증합니다.

프로젝트의 **τ·d 재설계** 버튼에서 CSV와 실행 전 허용폭을 입력합니다. 기존 결과는 보존하고 새 cycle·revision을 시작합니다. base별 공통 환경 시드를 사용하고 환경 RNG와 검토자 RNG를 분리합니다. 네 추정기의 base 공변량은 완전 교차가 아니므로 추정기 주변 차이를 순수한 성능 효과로 해석할 수 없습니다. 보고서 추정기 비교에서는 K0/K1을 제외하고 전량 검토 점검 기준선으로 명시합니다.

비열등성 옵션은 동일 추정기·τ·d·시나리오·환경 시드의 K0 전량 검토와 손실/FN/FP를 비교합니다. 손실 상대 허용폭, FN·FP 절대 허용폭은 실행 전에 정해야 합니다. UI 예시 0.10/0.01/0.01은 현실적으로 검증된 값이 아닙니다. 보수적인 동시 신뢰구간 대비를 현재 독립 배치에 적용하며 기존 절대 제약도 유지합니다. 경계와 통과 후보를 인위적으로 만들지 않습니다. 필요하면 사전 지정한 loss_mean_max도 직접 평균 손실 제약으로 사용합니다. K0 기준은 전량 인간 검토 정책이며 무오류 oracle 인간은 아닙니다.

## 인간 실험

- 서버가 지급금액·한도 판단 과제와 정답을 관리합니다. 신뢰도 .55/.75/.92에 맞춘 **통제된 권고 정답확률**이며 실제 AI 정확도로 표시하지 않습니다. UI가 ai_correct를 결정하지 않습니다.
- 참가자 pseudonym별 현재 cycle의 발급 상한 30회, trial 일회성 저장 및 중복 제출 방지를 적용합니다. 브라우저 식별자는 실제 사람의 고유성을 완전히 보장하지 않으므로 모집·중복 참여 관리는 실제 연구자의 책임입니다.
- 재설계 모델은 calibrated-task-v2의 서버 trial_id와 현재 cycle을 가진 관측만 사용합니다. 기존 실험을 새 프로토콜 데이터로 혼합하지 않습니다.
- 최소 참가자 30명, 정답·오답 각 60건 기준을 유지합니다. 표본 부족에서도 기술적 참가자 cluster bootstrap을 제공하지만 모델 승격은 HOLD입니다. 실제 참여자를 생성하거나 모집 기준을 충족한 것처럼 표시하지 않습니다.

## 보고서와 D1

실행 시나리오 키와 등록 소스 행, 에피소드를 구분합니다. Human은 현재 revision만 사용하고 다른 revision 기록 수를 설명하며 validations CSV에 revision을 추가했습니다. 추정기 신뢰구간에는 누락됐던 분모·비율을 연결했습니다. 참가자별 관측 수와 최대 비중, 신뢰도별 정답률, 기술적 cluster 구간도 표시합니다. 8~10절은 실제 데이터에 연결한 규칙 기반 내용으로 작성합니다. 실제 연구자가 최종 논의와 외적 타당성을 검토해야 합니다.

Historical·Stress 시나리오 자료가 없거나 후보의 비교 범위가 다르면 regret은 0이 아니라 미확정입니다. dashboard도 null을 0으로 변환하지 않습니다. 후보 및 작업 저장은 json_each 집합 쓰기로 변경했고 regret 갱신은 후보별 쿼리 대신 두 집합 쿼리입니다. 보고서 진단은 이미 읽은 실행 데이터와 참가자 집계를 재사용합니다.

## 검증과 적용

전체 테스트: **116 통과, 실패 0, 기존 Python 탐색 테스트 3개 건너뜀**. 재설계 회귀 10개와 Worker dry-run 성공을 확인했습니다. 로컬 브라우저에서 재설계 모달과 서버 인간 과제의 응답·revision 갱신을 확인했습니다. 테스트 관측은 로컬 메모리 DB에만 기록했습니다.

`npm run redesign:audit`는 첨부 208행에 기존 신뢰도·공통 신뢰도·완벽한 정답을 아는 점검용 기준선을 비교하고 임계값 민감도를 저장합니다. 완벽 정답 기준선은 배포 불가능한 진단이며 교정된 사후확률 oracle이 아닙니다. 합성 smoke 환경에서 16개 d=0→4 비교 모두 손실이 변했습니다. 공통 신뢰도 208개 셀 중 64개는 ECE>0.05였으므로 **확률 교정 완료나 80점 수준의 연구 결과를 주장할 수 없습니다**. 이 결과는 운영 연구 결과나 저널 제출 증거가 아닙니다.

Cloudflare 미로그인 상태로 원격 migration·배포·208개 운영 재실행은 수행하지 않았습니다. 적용 시 기존 D1 binding을 확인한 뒤 전체 migration(0019 포함)을 적용하고 배포합니다. 엔진·신뢰도 정책이 동결 프로토콜에 포함되므로 기존 프로토콜을 새 엔진으로 이어 실행하지 말고 재설계 버튼으로 새 cycle을 시작해야 합니다. 새 인간 표본을 모집하고, 별도 확인 자료에서 교정·민감도·paired 분석 및 최종 연구 문장을 검증해야 합니다.
